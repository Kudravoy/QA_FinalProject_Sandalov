# Дипломный проект по автоматизации тестирования: проведите smoke-тестирование веб-приложения Tandoor

## Описание проекта

Проект по автоматизации smoke-тестирования веб-приложения **Tandoor** — которое позволяет управлять рецептами и планировать питание.

### Цели проекта
- Автоматизация API-тестирования бэкенда Tandoor
- Автоматизация UI-тестирования веб-интерфейса
- Настройка CI/CD пайплайна в GitLab
- Генерация наглядных отчётов о тестировании (Allure)

### Технологии
| Технология | Назначение |
|------------|------------|
| Python 3.12 | Язык программирования |
| Pytest | Фреймворк для тестирования |
| Selenium WebDriver | Автоматизация браузера |
| Requests | HTTP-запросы для API-тестов |
| Allure | Генерация отчётов |
| GitLab CI/CD | Непрерывная интеграция |
| Docker | Изоляция окружения в CI/CD |

### Паттерны проектирования
- **Page Object Model (POM)** — для UI-тестов
- **API Client** — отдельный класс для взаимодействия с API
- **Fixture-based setup** — подготовка данных через pytest фикстуры

#### Необходимо учитывать, что ввиду недоступности официального сайта app.tandoor.dev с территории Российской федерации, приложение развёрнуто на сервере Eduson по адресу https://tandoor.vs1.srv.eduson.tv/, которое доступно с российских IP-адресов

## Инструкция по установке и запуску

### 1. Клонирование репозитория
```
bash
git clone https://gitlab.com/dmitriy_avl/QA_FinalProject_Avlov.git
cd QA_FinalProject_Avlov
```

### 2. Создание виртуального окружения
```bash
bash
# Windows
python -m venv .venv
.venv\Scripts\activate

# Linux/Mac
python3 -m venv .venv
source .venv/bin/activate
```
### 3. Установка зависимостей
```
bash
pip install -r requirements.txt
```
### 4. Настройка переменных окружения
Создайте файл .env в корне проекта.
* инструкцию по получению API-токена Tandoor и пример заполнения файла .env смотреть далее.

### 5. Запуск тестов
```
bash
# Запуск всех тестов
pytest tests/ -v

# Запуск только API-тестов
pytest tests/test_api_client.py -v

# Запуск только UI-тестов
pytest tests/test_ui_*.py -v

# Запуск конкретного теста
pytest tests/test_api_client.py::TestAPIClient::test_get_recipes -v

# Запуск в headless-режиме
$env:HEADLESS="true"; pytest tests/test_ui_*.py -v
```
### 6.Генерация Allure отчёта (локально)
```
# Установить Allure
# Windows: скачать и добавить в PATH
# Mac: brew install allure
# Linux: sudo apt install allure

bash
# Запустить тесты с сохранением результатов
pytest tests/ -v --alluredir=allure-results

# Сгенерировать отчёт
allure generate allure-results -o allure-report --clean

# Открыть отчёт
allure open allure-report
```

## Особенности, найденные при тестировании
1. Отсутствие стабильных атрибутов HTML как test-id и ID.
В интерфейсе Tandoor отсутствуют специализированные атрибуты для тестирования (data-testid или test-id). Существующие id являются динамическими и меняются при каждом обновлении страницы. Это усложняет поиск элементов и делает тесты более хрупкими.

2. Локализация интерфейса. 
При смене языка (русский/английский) меняются тексты на странице и форматы дат, что требует универсальных селекторов.


3. Поле поиска — в headless-режиме Enter может не срабатывать, требуется явный клик по кнопке поиска.

## Рекомендации по расширению покрытия тестирования
Для повышения надёжности и глубины проверок веб-приложения Tandoor предлагается реализовать следующие направления развития автотестов.

### 1. Негативные сценарии авторизации
В текущей реализации проверяется только успешный вход в систему. Рекомендуется добавить тесты на:

- вход с неверным паролем

- вход с несуществующим email

- пустые поля логина/пароля

- превышение лимита попыток входа (блокировка)

- вход с токеном, у которого истёк срок действия

- доступ к защищённым эндпоинтам без токена / с невалидным токеном

### 2. Пагинация в списке рецептов
При большом количестве рецептов интерфейс использует постраничную навигацию. Рекомендуется проверить:

- переход на следующую / предыдущую страницу

- отображение корректного номера страницы

- поведение при переходе за пределы последней страницы

- сохранение параметров сортировки/фильтрации при смене страницы

- количество элементов на странице соответствует настройкам

### 3. Дополнительные направления
| Область | Что проверить |
|------------|------------|
| Редактирование рецепта | Изменение названия, ингредиентов, шагов; проверка сохранения без потери данных |
| Удаление с подтверждением | Отмена удаления, подтверждение удаления, поведение при удалении используемого рецепта |
| Планирование питания | Пересекающиеся планы на одну дату, редактирование существующего плана, повторяющиеся события |
| Список покупок | Добавление/удаление позиций вручную, автоматическое объединение одинаковых ингредиентов |
| UI-кроссбраузерность | Проверка в Firefox, Edge (локально или через CI с использованием Selenium Grid) |
| Производительность API | Время ответа эндпоинтов при большом количестве рецептов (>100) |


### 4. Улучшение стабильности тестов
Учитывая отсутствие data-testid и динамические id, рекомендуется:

- разработать собственный слой абстракции для поиска элементов по тексту, ролям ARIA или комбинации CSS-классов

- использовать кастомные ожидания (ожидание стабильности DOM перед взаимодействием)

- внедрить автоматические повторные попытки для хрупких операций (например, через pytest-retry или повторные вызовы внутри теста)

### 5. Интеграционное тестирование
Проверка сценария: создание рецепта через API → отображение в UI → добавление в план питания → генерация списка покупок → удаление через UI

Синхронизация данных между разными вкладками браузера (одновременная работа с одним аккаунтом)

### 6. CI/CD расширения
Добавить параллельный запуск тестов (pytest-xdist) для сокращения времени выполнения пайплайна

Настроить ежедневный ночной прогон всех тестов (cron в GitLab CI)

Внедрить автоматическую публикацию Allure-отчёта в GitLab Pages

### 7. Приоритетность внедрения
| Приоритет | Задача | Ожидаемая ценность |
